# Todo

優先度を4分類して整理する、iPhone向けのローカルファーストTodoアプリ。Expo SDK 58 / React Native / TypeScriptで実装しています。

## 起動

Node.js 24、Xcode、CocoaPodsが必要です。ウィジェットはExpo Goでは動かないため、iOS開発ビルドを使います。

```sh
nvm use
npm ci
npm run ios
```

最初にアプリを開いてから、ホーム画面のウィジェット追加で「Todo」を選んでください。ロック画面の追加はロック画面のカスタマイズから行います。実機ではApple Developerの署名とApp Groupの利用設定が必要です。

画面・保存操作のWebプレビューは `npm run web` で開けます。WebにはiOSウィジェットはありません。

## 実装内容

- ひとつの未完了一覧を「緊急かつ重要」「重要だが緊急ではない」「緊急だが重要ではない」「緊急でも重要でもない」の見出しと細い区切り線で分類。空の分類も見出し・件数・追加ボタンだけで表示。
- 分類内は期限日時の昇順、期限なしは最後。同じ期限・期限なし同士は手動順を維持。上下ボタンで並べ替え。
- タスクの追加・編集・削除・完了・未完了への復元、期限日時とメモの編集。
- 端末内にタスク・設定・下書きを保存。編集中の終了時は下書き保存・破棄・継続を選択。別の下書きの上書きは確認してから実施。
- 保存処理は1つの文書に対する直列書き込み。保存に失敗した変更は確定せず、破損した保存データも勝手に初期化しません。
- オフホワイトを初期配色にし、設定から「オフホワイト」「ダーク」「端末に合わせる」を選択。配色は端末内に保存し、既存データに配色設定がなければオフホワイトで開く。ステータスバー・日時入力も配色に追従。
- 標準の文字サイズ拡大、操作ラベル、分類名による色以外の識別。完了一覧にも元の分類名を表示。

## ウィジェット

`expo-widgets`でApp Group、WidgetKit拡張、タイムラインの永続化と更新を設定しています。アプリのReact状態・Hooks・Contextはウィジェットから参照しません。アプリから渡す表示用データにメモは含みません。

ホーム画面は小・中・大に対応。共通ロジックで並べた未完了タスクを表示し、タイトルは最大2行、分類ラベルと期限を添えます。SwiftUIの実際の領域とDynamic Typeに対応したフォントの計測から、残件数欄も含めて収まる最長のタスク列を選びます。件数はサイズ別の固定値にしていません。残りは「ほかにあと○件」で表示します。

公開されているExpo UIのウィジェットAPIには領域・文字高の計測機能がないため、ホーム画面の描画だけをSwiftUIで補完しています。`plugins/with-adaptive-todo-widget.js`がprebuild時に、Expoの生成したホーム画面用ファイルへアプリ所有のSwiftUIコードを組み込みます。Expo本体やnode_modulesを変更するパッチはありません。プラグインは実行順の都合で `app.json` の `expo-widgets` より前に記載してください。生成テンプレートが変わった場合は黙って適用せずエラーにします。

ロック画面はインライン・円形・長方形に対応。「今日」は端末の現地日付で、期限日が今日の未完了タスクです。「次」は分類をまたいで期限が最も近い未完了タスク（期限超過も含む）。期限のあるタスクがなければ4分類の並び順で選びます。

ロック画面の表示枠はiOSが決める3形式です。横長は左に今日の件数、細い区切りを挟んで右に次のタスク名（最大2行）と期限を置きます。件数のみ・次のタスクのみの場合は空いた幅を使います。円形はOSのAccessoryWidgetBackgroundに件数を大きく表示し、次のタスクのみなら矢印と短いタスク名を表示します。時計上の1行型はチェックリストの記号と短い要約です。固定の白・黒や分類色に頼らず、OSの前景色と階層表現を使います。0件とタスクなしは区別し、数字は等幅、1000件以上は小さな枠では「999+」（VoiceOverには正確な件数）にします。両方オフならTodoの表示だけを残します。

次のタスクの期限表示も日付切替で更新するため、件数の表示をオフにしていてもタイムラインを予約します。次タスクをオフにした場合は、タスク名に加えて期限・空状態の情報も共有データから除外します。

`node scripts/preview-lock-widgets.cjs` で、実際のExpoウィジェット描画ランタイムからデザイン確認用HTMLを `.artifacts/previews/lock-widgets.html` に生成できます。明るい壁紙・暗い壁紙、各表示設定の確認用で、iOSの実画面や正確な機種別サイズを再現するものではありません。確認画像は `lock-widgets.png` にあります。新しいロック画面レイアウトの実機表示は未確認です。

ロック画面の件数と次タスクは設定で独立に切り替えられ、オフの情報はロック画面用データからも除きます。長方形・インラインでは両方、円形では件数を優先して表示。両方オフでは「Todo」のみを表示します。期限日とその翌日の現地午前0時に切り替わるタイムラインを予約します。タイムゾーン変更後はアプリを開くと作り直します。

追加・編集・完了・復元・削除・並べ替え・設定変更後とアプリの再開時に更新します。iOSが更新タイミングを制御するため、ホーム画面への即時反映は保証されません。

全体タップは `todo-performance:///` で一覧へ、中・大サイズのタスク行は `todo-performance:///task?id=...` で編集画面へ移動します。小サイズとロック画面は一覧を開きます。

ホーム画面ウィジェットにも配色設定を渡し、SwiftUI側にオフホワイト・ダーク・端末に合わせる描画を実装しています。この描画変更をインストール済みのウィジェットに反映するにはprebuildとiOSアプリの再ビルドが必要です。今回の画面変更ではネイティブビルドは実行していません。ロック画面はiOSの描画に従います。

ウィジェット上の完了操作は現在未実装です。iOS 17以降の対話型ウィジェットでは追加可能ですが、現在のAsyncStorageの保存データとApp Intentをつなぎ、アプリ終了中の完了操作・再開時の整合性・予約通知の取消を実装する必要があります。

## 仮設定と環境上の制約

名称は「Todo」、ベースはオフホワイト、アクセントは落ち着いたグリーン、最低対応iOSは16.4。バンドルIDは `com.nagaiasuka.todo`、App Groupは `group.com.nagaiasuka.todo` です。正式名称・公開用アイコン・配布用IDと署名は公開前に確定してください。手動並べ替えは上下ボタンで、ドラッグ操作は含みません。Androidは初期対象にしていません。

このMacのRuby 4 / CocoaPodsでは、日本語を含むリポジトリパスでReact Nativeのpodspec処理に文字コードエラーが発生しました。英数字のみのパスにコピーしてネイティブビルドを検証しました。同じエラーが出る環境では英数字のパスへチェックアウトして `npm ci` → `npm run ios` を実行してください。

macOSの `/tmp` と `/private/tmp` のような別名のあるパスでは、Expoのウィジェット用バンドラーがソースを解決できない場合があります。この検証ではXcodeの `PROJECT_ROOT` ビルド設定に実パスを指定して解消しました。通常のチェックアウト先でも、シンボリックリンクを介さないパスを使ってください。

アカウント・クラウド同期・課金・広告・ウィジェット上での完了操作は実装対象に含みません。

### リマインダー

タスク編集の「リマインダー」で期限とは独立した通知日時を指定できます。iPhone上のローカル通知を1回予約します。通知を設定したタスクの保存時にだけ通知許可を求めます。拒否された場合は入力内容を残し、iPhoneの設定で通知を許可するか、リマインダーをオフにして保存できます。

期限日時を設定すると、「10分前」「30分前」「1時間前」のボタンで通知日時を選べます。ボタンを押すとリマインダーもオンになります。過去になる通知日時は設定せず、案内を表示します。通知日時は引き続き直接変更できます。期限日時を後から変更した場合は、ボタンをもう一度選んでください。

完了・削除・リマインダー解除時には予約を取り消し、タスク名・日時変更時には予約を更新します。未完了に戻した場合は未来の日時に限って再予約し、過去の通知を即時発火させません。起動・フォアグラウンド復帰時にも保存データとOSの予約を照合し、失敗した場合は一覧に再試行の案内を表示します。通知タップで該当タスクを開きます。通知にメモは含めません。

未通知のリマインダーは最大60件です。ブラウザー版では通知できません。既存の保存データに通知日時がなくても読み込めます。日時を変更しなければ、過去の通知日時が残ったタスクも編集できます。通知の表示・音はiOSの通知設定や集中モードに従います。

`expo-notifications`（SDK 58互換）を追加したため、**リマインダーを使うにはiOSアプリの再ビルド・再インストールが必要です**。以前の開発ビルドでも一覧などは開けますが、通知設定の保存時には再ビルドが必要な旨を表示します。Macの高負荷を避けるため、今回ネイティブビルドは実行していません。再ビルド後、1〜2分後の通知、完了・削除による取消、通知タップ、許可拒否からの復帰を実機で確認してください。ウィジェット同様、通知の実機表示は未確認です。

公式資料: [Expo SDK 58 Widgets](https://docs.expo.dev/versions/v58.0.0/sdk/widgets/)、[Expo Router 58の変更点](https://docs.expo.dev/router/migrate/sdk-57-to-58/)。
